### How It Works
1. **Cython 3.0.11** transpiles your `.py` into real C (`/* Generated by Cython */`, ~270+ KB of C per demo).
2. A genuine **Visual Studio 2022** project (`.vcxproj` + `.sln`, toolset v143, x64 Release) wraps that C file.
3. **MSBuild** compiles it to EXE — Visual Studio auto-generates the debug binaries (`.pdb`) via `/Zi` + `/DEBUG`.
4. The stdlib is staged as `python314.zip` plus the required `.pyd`/`.dll` files next to the EXE, so it boots on a PC with no Python installed. No Debug CRT (`*_d.pyd`) is ever shipped.

```
python -m cpythonizer vs-build examples/single_hello.py --name Hello --dist dist
```

Function names and metadata remain visible (Cython keeps them as module attributes),
but **no bytecode, no source logic, no constants can be reconstructed** — the actual
code is native machine code produced by MSVC. Static decompilers (Hexpyrion-style)
get nothing at all, since there is no frozen `.pyc` to extract — unlike Nuitka
onefiles, which ship recoverable bytecode.
